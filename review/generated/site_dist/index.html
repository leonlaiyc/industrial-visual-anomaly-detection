Case study · Industrial visual inspection · Public benchmark data

Flagging circuit-board images for human review: fewer false alarms, same defect recall

A prototype that learns only from defect-free board images and ranks new images for a quality engineer’s attention. It was tested once, under a protocol written before the data was opened, on a board type held back from development.

What was built
A one-class detector: frozen pretrained CNN features, a per-position Gaussian model of normal appearance, board registration, and — in v2 — a score taken over the board region only. Thresholds are set on separate normal images and frozen before testing.
Unresolved risks
  • Recall 80% against a proposed 90% target.
  • A 10% darker image raises false alarms by +25.1 pts.
  • Small defects: 56% recall in the smallest third.
Recommended next decision
No-Go for a manufacturing pilot. Fund only a bounded validation step: confirm requirements with a real quality engineer and test the open risks before any further model work.

Delivery path

Seven stages, with what this project actually did at each. Stages two and three were drafted only as proposals before testing; in a real engagement they would come first, with the users.

  1. 1 Understand the problem Done Board pose, lighting and background inspected on training images only; one-class learning chosen because defects are rare and varied.
  2. 2 Requirements and decision value Partly done Proposed targets and Go/No-Go rules fixed before any test. Cost-sensitivity analysis added afterwards; no user has confirmed either.
  3. 3 First-Time-Right alignment Proposed Proposed review workflow and interface mock-up built from real model output, with an acceptance checklist for a real user to confirm.
  4. 4 Model selection and implementation Done Frozen-feature Mahalanobis detector, implemented and unit-tested; alternatives compared on labels, objective and cost.
  5. 5 Controlled experiments In progress PCB1 discovery, one pre-registered change, a single confirmatory run on PCB2; one controlled illumination experiment on PCB3.
  6. 6 Go / No-Go Partly done Rule-based verdict against the unchanged criteria; recommendation: no pilot yet.
  7. 7 Site readiness and handoff Partly done Each observed failure mapped to what a new site must validate; versioned handoff with gates, rollback and escalation.

Terms used on this page
Recall
Share of defective boards that the tool sends to human review. A missed defect is a defective board it does not flag.
False-alarm rate
Share of normal boards that the tool sends to review. Because the tool only recommends a review — it never rejects or scraps a board — a false alarm costs reviewer time, not product.
AUROC
Threshold-free ranking quality: the probability that a random defective board scores higher than a random normal one.
Frozen threshold (P95)
The score above which an image is flagged, set from separate normal images to target about 5% false alarms, and fixed before any test image is scored.
Pre-registration
Writing the hypothesis, data split, endpoint and decision rule into the repository before the test data is opened, so results cannot steer the analysis.
Shadow mode
Running the tool alongside the existing inspection without affecting any decision, to measure it on real production images.
